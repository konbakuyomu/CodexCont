# Trellis CodeStable bridge CLI design

## Architecture

`vibe-flow` is a Python standard-library CLI with three internal layers:

- `TrellisAdapter`: read `.trellis/` files and, when safe, call Trellis read-only
  scripts.
- `CodeStableAdapter`: read `.codestable/` aggregate-root directories and infer
  the most specific current unit and stage.
- `BridgePlanner`: combine user intent with both adapters and return a stable
  `next_action`.

The CLI does not import Trellis or CodeStable internals. It treats their files
and helper scripts as external contracts.

## Public commands

```bash
python -m vibe_flow init
python -m vibe_flow doctor --json
python -m vibe_flow status --json
python -m vibe_flow next --intent "<user text>" --json
python -m vibe_flow run next --json
```

Convenience wrappers named `vibe.py` and `vibe` can call the same module entry
point. The tests use `python -m vibe_flow` so they work on Windows.

## JSON contract

All JSON commands return:

```json
{
  "schema_version": 1,
  "mode": "codestable_passthrough",
  "trellis": {},
  "codestable": {},
  "next_action": {}
}
```

`doctor` adds `diagnostics`. Errors are structured with `ok: false`, `error`, and
`diagnostics` where possible instead of raw tracebacks.

## Stage inference

Feature stages are inferred from canonical CodeStable files:

- no design -> `not_started`
- design exists, no design-review -> `design_draft`
- design-review exists but design not approved -> `design_review_passed`
- approved design, no review / qa / acceptance -> `approved`
- review missing after implementation marker -> `implementation_done`
- review passed, no QA -> `review_passed`
- QA failed / blocked -> `qa_failed`
- QA passed, no acceptance -> `qa_passed`
- acceptance passed -> `accepted`

Approval is detected conservatively from YAML frontmatter or body markers such as
`status: approved`, `decision: approved`, or `approved: true`.

## Intent handling

- Explicit `cs-*` intent -> `codestable_passthrough`.
- Continue / complete / autonomously finish / `cs-goal` takeover -> `bridge_autopilot`.
- Trellis present but CodeStable unit absent -> `trellis_first`.

When multiple active CodeStable candidates exist, the planner returns
`next_action.kind = "ask_owner"` with concrete candidates instead of guessing.

## Safe execution

`next` is read-only. `run next` may run only commands generated by the planner
with `safe: true`; for v1 this is limited to read-only helpers and a Trellis
`task.py start` proposal when explicitly selected by the stage map. Owner-gated
actions are never executed.

## Project init

`init` creates:

- `.vibe-flow/config.yaml`
- a managed `AGENTS.md` block between `<!-- VIBE-FLOW:START -->` and
  `<!-- VIBE-FLOW:END -->`

It does not run `trellis init` or `cs-onboard`.

## Compatibility

- Use repo-relative paths in output when possible.
- Support Windows paths and UTF-8 content.
- Avoid deleting files or cleaning unrelated dirty state.
- Avoid new runtime dependencies.

## Platform

web

## Users

- **Key 持有人（主要用户）**：维护者把 CPA 原生 `sk-` Key 分发给朋友和同事。他们打开「CPA 用量自助页」（`cpa-usage.konbakuyomu.us`），用自己的完整 Key 登录，只能看到自己这把 Key 的额度、花费和请求明细。电脑和手机都常用：写代码时请求被拦，会到电脑上查原因；碎片时间会在手机上看还剩多少。
- **维护者（管理员）**：在 CPAMP 左侧菜单「CPA Key Policy+」里维护每把 Key 的启用状态、RPM、模型白名单、四个美元额度窗口和软重置。维护者住在美国、远程上班，车友多在国内，所以额度与重置时间一律按北京时间显示。
- **车主与车友（拼车）**：维护者是车主，和同事拼 ChatGPT 订阅号（一个 Pro 20x、一个 Plus）。每个号的周限按百分比分给车友；车主不受份额限制。车友要随时看到自己还剩多少份额、号本周用了多少、什么时候重置。

## Product Purpose

CPA Key Policy+ 是 CLIProxyAPI（CPA）的插件，负责普通用户原生 `sk-`/`sk_` Key 的认证、RPM、模型白名单、滚动额度窗口（5 小时 / 24 小时 / 7 天 / 北京时间本月，单位美元）、用量记账和软重置。

成功意味着：Key 持有人能自己回答「还能不能用、还剩多少、为什么被拦、钱花在哪」，不用来问维护者；维护者能一眼看出哪些 Key 缺策略、接近上限或被冻结，并在 CPAMP 里直接处理；拼车时，车主能实时看到每个号的周线（本周期折算走势）、月线（每日收盘）和每个人的用量热力图，车友能随时看到自己的份额余量。

## Positioning

用户页、管理页和 CPA/CPAMP 用的是同一份事实：Key 身份跟随 CPA 当前配置，单价跟随 CPAMP 模型价格表，用量与额度来自插件自己的数据库。两个页面看到的是同一套数字，不再出现「Docker 一套、CPA 面板一套、CPAMP 又一套」的割裂。

## Operating Context

- 用户页经 CPA 插件资源路由 `/v0/resource/plugins/cpa-key-policy-plus/user` 对外提供；登录时用 `X-CPA-Key-Policy-Plus-Key` 请求头提交完整 Key，换取 24 小时 HttpOnly 会话 cookie。资源路由只接受 GET。
- 管理页是 CPAMP 的插件菜单页，被 CPAMP 用 iframe 嵌入。CPAMP 会往页面里注入宿主主题：`data-theme`（`dark` / `white`）、`cpamp-plugin-host` 类、全部 CPAMP CSS 变量，以及带 `!important` 的按钮、输入框、表格、`span/label/small/dt/dd` 颜色和类名含 `card`/`panel` 元素的样式。
- 页面 HTML/CSS 通过 `go:embed` 编进插件 `.so`；改页面必须重新编译并部署插件，镜像自动升级不会替换插件。
- 5 小时、24 小时、7 天是滚动窗口；「本月」按北京时间自然月计算。
- 拼车数据来自 CPA 交给插件的每条用量记录：记录里有服务这次请求的上游凭证（`auth_index`）和上游响应头的快照，其中 `x-codex-*` 头带着这个号的周限百分比、窗口长度和重置时间。周窗口按长度（约 10080 分钟）识别：Pro 号放在 primary，Plus 号放在 secondary、primary 是 5 小时窗口。不需要管理密钥，也不主动请求上游。
- 周限百分比是整数，号的周容量（100% 对应多少美元）每天都在变，这是拼车分账的难点：插件把每次百分比跳动按两次跳动之间各人完成的花费比例分给大家（逐跳分摊），跳动之间的花费按本周期实测折算估为待定。记录到的花费解释不了的跳动（有人在 CPA 之外直接用号）留在「未归属」，不算到车友头上。
- 固定到号：给 CPA 里每个号的凭证设置前缀（如 `pro`、`plus`），插件在 `model.route` 里把拼车成员的 `gpt-5.5` 改写成 `pro/gpt-5.5`，只有带该前缀的凭证会接。只有 CPA 模型列表里真的有前缀模型时才改写；没设前缀就继续原来的轮换。拒绝仍由请求拦截器返回真实 429，路由从不承载拒绝。

## Capabilities and Constraints

- 用户页：只接受完整原生 `sk-`/`sk_` Key，拒绝已下线的 `cpa_` Key 和列表里的截断预览；显示额度窗口（`weekly_only` 模式只显示滚动 7 天）、调用次数与成功率、Token / 思考量 / 缓存、请求明细与费用组成、费用待核算提示；页面可见时每 5 秒刷新。
- 管理页：Key 的新增、删除、复制和别名在 CPA/CPAMP 里完成，这里只维护 Plus 策略（启用、RPM、模型白名单、额度窗口、软重置）；模型目录镜像 CPA `/v1/models`；价格统一跟随 CPAMP。
- 只设置 7 天额度、其余窗口留空，即为「仅周额度」模式。
- 缺价模型不会按 $0 放行：事件记为 `billing_pending`，Key 被冻结，直到 CPAMP 补价后由管理员重新结算。
- 已退役、不得回到界面的能力：请求并发与 Codex 活动窗口限制、CodexCont / 思维链保护视图、Plus 侧的 Key 创建/删除/复制。
- 页面自包含：CSS 与 JS 内联，不依赖外部字体或 CDN（使用者可能在中国大陆访问；页面由插件直接返回）。
- 本轮确认新增：会话恢复与真正退出；请求明细分批加载、只看失败、按模型筛选；管理页补齐待核算一键重新结算、「仅周额度」模式显示、Key 搜索、未保存改动提示；用量趋势图（需要后端新增聚合接口）。
- 拼车（本轮新增，参考 Sub2Pool 与 SubCard 的思路，未使用其代码）：
  - 拼车池 = 一个上游号 + 一组 Key；一把 Key 只属于一个池；份额是号周限的百分比，合计不超过 100%；勾「车主」的 Key 不限额。
  - 车友份额用完就直接拦截（只拦这个号能接的模型），消息写明何时重置。
  - 临时爽蹬：到本周期结束前不按份额拦截。开启时二选一：结转（超出份额的人下个周期按比例还给没用完的人，零和，闲置份额作废，5 位小数记账）或不结转（多用不追、少用不补，必须先告知所有车友）；提前终止即取消本轮结转。
  - 车友可见范围按池设置：匿名（默认，车友 A/B/C）、实名、只看自己。
  - 用户页加「拼车份额」一栏和 `?view=card` 小票卡片；「钉到桌面」用浏览器的画中画窗口把卡片置顶在屏幕角落（Chrome/Edge），不支持时打开小弹窗。不做原生 App、不做 PWA。
  - 可选：配置 `sub2pool_url` 与 `sub2pool_api_key` 后，在管理页并列显示 Sub2Pool 的折算做对照，不影响记账。
  - 只做核心功能，不复刻参考项目里分散的研究面板和轨迹图。

## Brand Commitments

- 名称：管理页「CPA Key Policy+」（CPAMP 菜单名），用户页「CPA 用量自助页」。
- 管理页融入 CPAMP：跟随 CPAMP 的亮/暗主题与控件习惯（维护者确认）。用户页拥有自己的视觉。
- 拼车相关内容收拢在一处：管理页一个号一个区块（数字、周线/月线、成员表与热力图、爽蹬），用户页一栏份额，不拆成多个页面。
- 中文界面，保留通用英文技术词：Key、Token、RPM、TTFT、Service Tier、Reasoning Effort。

## Evidence on Hand

- 真实数据只存在于生产数据库；仓库里没有生产截图。
- 本地预览数据全部为合成数据，不得当作真实用量、价格或用户展示。
- 不得编造价格、额度或用户数量。
- 部署当时的只读观察（2026-09-27）：CPA 里有一个 Pro 号（周窗口在 primary，已用 5%）和一个 Plus 号（5 小时窗口 100%、周窗口 16%，状态异常），两个号都还没设前缀；路由策略 fill-first + 会话粘性。

## Product Principles

- 数字只有一个来源：前端不重算额度和价格，展示后端给出的值；未知就写未知。
- 先回答「还能不能用」：额度状态、拦截原因和恢复方式排在统计细节之前。
- 不确定要明说：价格待核验、同步失败、会话过期都用文字说明，不拿 $0、空白或旧数据掩盖。
- 管理页是 CPAMP 的一部分，用户页是持有人自己的账单。
- 完整 Key 不出页：界面只显示预览。

## Accessibility & Inclusion

状态必须同时有文字，不能只靠颜色；全部操作可用键盘完成并有可见焦点；手机宽度（390px）下无横向页面滚动；尊重 `prefers-reduced-motion`。
